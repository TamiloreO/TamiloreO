# Roadmap

The site is being rebuilt from a single scrolling page into something you walk through. The goal for v2: one small 3D world, a character you control, and every project or technology I have worked with is a thing you can walk up to and interact with, instead of a card in a list. A short 2D turn-based encounter (think early Pokemon battles) sits inside it as a way to show one part of my work.

Estimates are working hours, not calendar time.

## Phase 1: the 3D shell (about 8 hours)

- [ ] Move `website/` behind `/classic`, keep v1 reachable so nothing is lost while v2 is built.
- [ ] Add Vite and TypeScript with a single entry point, and a build that still outputs a static folder Pages can serve.
- [ ] Stand up a Three.js scene: ground plane, sky, directional and ambient light, a fixed camera, resize handling.
- [ ] Get a first-person walk working with WASD before adding a visible character, to prove the pipeline.

Done when: a static build renders a lit room and I can move around it on desktop.

## Phase 2: a character I control (about 10 hours)

- [ ] Load a rigged low-poly character and play idle and walk clips through an animation mixer.
- [ ] Third-person camera that follows with damping, and a mouse or arrow-key orbit.
- [ ] Move with velocity rather than by teleporting the model, so animation and movement match.
- [ ] Collision against walls and props with Rapier, a capsule body, and a walkable floor.
- [ ] Touch controls: a virtual stick and a drag area for the camera, so it works on a phone.

Done when: the character walks around a room without passing through walls, on desktop and on a phone.

## Phase 3: the world and its stations (about 8 hours)

- [ ] Lay out a hub: an entrance, a main hall, and one station per project (portfolio v1, TouchAR, the chat server, the traffic simulator).
- [ ] Each station gets signage, a pedestal, and a readable label so the space explains itself without a menu.
- [ ] Proximity detection: when the character is near a station, show a prompt.
- [ ] A day and night pass, or a fixed moody lighting preset that suits the terminal aesthetic.

Done when: I can walk from the entrance to any project station and know what I am looking at.

## Phase 4: interaction and content (about 8 hours)

- [ ] Interact key (E or a button) opens a panel for the station's project: what it is, what I did, the stack, links to the repo and the live version.
- [ ] Panels are real DOM overlays, not texture maps, so text stays selectable, searchable and accessible.
- [ ] Focus management: opening a panel traps focus, Escape closes it, and the camera does not fight the cursor.
- [ ] Move the v1 content into these panels so there is one source of truth.

Done when: every station opens a panel with real content and the page is usable with a keyboard alone.

## Phase 5: the turn-based mini-game (about 10 hours)

- [ ] A 2D battle screen in its own scene: my character against a "bug" drawn from a real issue I fixed.
- [ ] Turn order, three moves, health bars, and a win and lose state.
- [ ] Moves map to real debugging actions (bisect, add a test, revert) so the joke lands.
- [ ] Enter it from one station, return to the hub when the battle ends.

Done when: the battle can be played start to finish and exited without reloading the page.

## Phase 6: performance, access and ship (about 6 hours)

- [ ] Budget the scene: target 60 fps on a laptop, cap the draw calls, instance repeated props, compress textures.
- [ ] Respect `prefers-reduced-motion`: no camera bob, no idle sway, shorter transitions.
- [ ] Fall back to the v1 site automatically when WebGL is unavailable.
- [ ] Wire the Pages deploy to the new build output and keep the old URL working.

Done when: the deployed site loads in under three seconds on a mid-range phone and degrades to v1 without errors.

## Later, if it holds up

- Save position and unlocked panels in `localStorage`.
- A second room for writing and notes.
- Optional: a tiny backend for a guestbook, only if static hosting stops being enough.
